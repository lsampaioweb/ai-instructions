# Database Schema Rules

See `spring-boot-soft-delete.instructions.md` for entity lifecycle rules based on soft delete columns and restore semantics.
See `spring-boot-referential-integrity.instructions.md` for foreign-key delete behavior and conflict policy.

## Scope
- Use this file as the canonical source for relational schema naming and type-sizing conventions.
- Apply these rules to DDL and SQL mapper artifacts.

## Integer Type Sizing
- Choose the smallest integer type that satisfies the domain growth expectation.
- Prefer `SMALLSERIAL` for bounded reference tables with low cardinality.
- Prefer `SERIAL` for general business tables with moderate growth.
- Use `BIGSERIAL` only for high-volume tables where 32-bit ranges are insufficient.
- Do not default to `BIGSERIAL` without a volume-based reason.

## Character and Text Types
- Use `VARCHAR(N)` when a business maximum length exists.
- Align `N` with explicit domain validation rules.
- Use `CHAR(N)` only for truly fixed-length values (for example: ISO country code).
- Use unbounded text types only when variable free-form content is required.

## Naming Conventions
- Use `snake_case` and plural names for table names.
- Use `snake_case` for column names.
- Use explicit constraint and index names.
- Use `fk_<table>_<column>` for foreign keys.
- Use `idx_<table>_<column>` for non-unique indexes.
- Use `uq_<table>_<column>` for unique constraints.

## Nullability and Constraints
- Treat `NOT NULL` as the default for columns.
- Use nullable columns only when the domain explicitly allows absence.
- Declare foreign keys explicitly and keep referenced columns indexed.
- Avoid implicit constraint names generated by the database.

## Referential Integrity Policy
- Explicitly declare `ON DELETE` behavior for every foreign key.
- Choose `RESTRICT`, `CASCADE`, or `SET NULL` based on domain lifecycle rules.
- Keep delete behavior consistent with API semantics and error handling contracts.

## Documentation and Review
- When deviating from these defaults, record the reason in the change summary.
- Keep schema and application validation rules aligned to avoid persistence-time surprises.
